NiceGUI lets you go from a blank file to a running browser UI in minutes. This guide walks you through installation, a minimal working example, and a slightly richer app that demonstrates pages, layout, inputs, and data binding. No frontend knowledge required.

## Basic Setup

<Steps>
  <Step title="Install NiceGUI">
    NiceGUI is available on PyPI. Install it with pip:

    ```bash
    pip install nicegui
    ```

    Python 3.10 or newer is required. See [Installation](/installation) for conda, Docker, and optional extras.
  </Step>

  <Step title="Create main.py">
    Create a file called `main.py` with the following content:

    ```python
    from nicegui import ui

    ui.label('Hello, NiceGUI!')
    ui.button('Press me', on_click=lambda: ui.notify('Button was pressed!'))

    ui.run()
    ```

    - `ui.label` renders a text element.
    - `ui.button` renders a clickable button; `on_click` is a plain Python callable.
    - `ui.notify` shows a brief toast notification in the browser.
    - `ui.run()` starts the FastAPI/Uvicorn server and (by default) opens a browser tab automatically.
  </Step>

  <Step title="Run the app">
    ```bash
    python main.py
    ```

    You will see output similar to:

    ```
    NiceGUI ready to go on http://localhost:8080
    ```
  </Step>

  <Step title="Open the browser">
    Navigate to [http://localhost:8080](http://localhost:8080). You should see the label and button. Click the button — a notification appears in the corner of the page.

    <Tip>
      NiceGUI watches your source files and **automatically reloads the browser** when you save a change. You do not need to restart the server during development.
    </Tip>
  </Step>
</Steps>

## A More Complete Example

The snippet below introduces several concepts you will use in real apps: the `@ui.page` decorator, layout containers (`ui.row`, `ui.column`), an input element, and two-way data binding.

```python
from nicegui import ui


@ui.page('/')
def index():
    # module-level state would be shared across all users;
    # declaring it here makes it per-visitor
    name = {'value': 'World'}

    with ui.column().classes('p-4 gap-4'):
        ui.label('Greeting demo').classes('text-xl font-bold')

        with ui.row().classes('items-center gap-2'):
            ui.label('Name:')
            name_input = ui.input(
                placeholder='Enter your name',
                on_change=lambda e: greeting.set_text(f'Hello, {e.value}!'),
            )

        greeting = ui.label(f'Hello, {name["value"]}!')

        ui.button(
            'Reset',
            on_click=lambda: (
                name_input.set_value(''),
                greeting.set_text('Hello, !'),
            ),
        )


ui.run(title='Greeting Demo')
```

Key patterns demonstrated here:

| Pattern | What it shows |
|---|---|
| `@ui.page('/')` | Each browser visit runs this function once, creating an isolated scope per user |
| `with ui.column():` | Context manager — child elements are placed inside the column automatically |
| `ui.input(on_change=...)` | Input element whose `on_change` callback fires on every keystroke |
| `element.set_text(...)` | In-place update — updates the existing element without destroying and recreating it |

### Binding variant

The same greeting can be written with NiceGUI's declarative binding system, removing the manual callback:

```python
from nicegui import ui


@ui.page('/binding')
def binding_demo():
    class State:
        name: str = 'World'

    state = State()

    with ui.column().classes('p-4 gap-4'):
        ui.input('Name').bind_value(state, 'name')
        ui.label().bind_text_from(
            state, 'name', backward=lambda v: f'Hello, {v}!'
        )


ui.run()
```

`bind_value` establishes a two-way link between the input and `state.name`. `bind_text_from` derives the label's text from `state.name` through a transform function. Both update automatically — no `on_change` handler needed.

<Note>
  Hot reload is enabled by default (`reload=True` in `ui.run()`). It only watches `*.py` files in the current directory. To disable it in production, pass `reload=False`.
</Note>
